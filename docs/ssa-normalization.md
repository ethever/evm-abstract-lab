# SSA 基础规范化与值事实

CLI 和 Web 默认输出一份经过基础规范化的 SSA。它保持逐条指令、原生状态和转移，执行常量传播、常量折叠及基础代数简化；每个原值定义仍然存在，最终 ValueId 在本报告内连续编号。复杂表达式不会被嵌入消费者，CFG、调用和返回结构也保持不变。

## 从实际输出理解变化

```bash
nix run . -- ssa --hex 600260030100
```

指令正文为：

```text
0000: %0 = CONST 0x2 ; origin=PUSH1
0002: %1 = CONST 0x3 ; origin=PUSH1
0004: %2 = CONST 0x5 ; origin=ADD
0005: STOP
```

ADD 的结果变成常量定义，原来的两个常量定义继续保留。原 PC、opcode、操作数、结果、故障与执行阶段仍可查询；`CONST` 描述值计算，`origin=ADD` 说明原执行步骤。普通操作的已知参数也可以直接显示为常量，例如 `ADD 0xa %6`。

对于未知 `%x`，`ADD %x 0` 可以成为 `COPY %x`。COPY 的结果仍有自己的 ValueId，它与 `%x` 的等价关系单独记录。当前不消除 φ，也不执行无用值定义清理。求值复用 EVM 256 位运算规则，覆盖回绕、除零、有符号运算和移位；相同区间、候选集合或来源类别不表示两个值相等。

## 计算、执行证据与事实

| 信息 | 回答的问题 |
| --- | --- |
| 指令 `operation` | 规范化之后，这个值怎样计算？ |
| 原指令字段、phase 和 effect | 原来执行了哪个步骤，到了哪个阶段，效果怎样连接？ |
| 值事实与来源映射 | 这个值已知什么、事实在哪个范围成立、为什么得到这个结果？ |

值表达式简化后，原执行效果仍存在。已知读取结果可以表达为常量，但这没有删除读取或内存扩展的执行证据。CALL/CREATE 的结果仍在调用恢复转移上定义；待定、故障或只消费了操作数的步骤不会获得正常结果。

实现先使用原始 SSA 验证器核对执行回执，再构建并验证规范化结果。临时构建形式用于校验，用户输出只包含一份最终 SSA。原有字节码身份、覆盖与效果验证没有放宽。[核心入口](../crates/evm-abstract/src/ssa/normalized.rs)、[规范化验证](../crates/evm-abstract/src/ssa/normalized/verify.rs)。

## 值事实的作用范围

逐指令数值与来源投影在正常结果产生时采集，和该次执行回执关联。采集保存 `NumericValue` 与 provenance，不复制整份机器状态或符号表达式树。入口变化时，旧回执及其指令结果事实一起失效；摘要回放保留相应的不可变证据。

- `Definition`：在本报告声明的输入与覆盖条件内，保证对这个定义成立，可以作为基础规范化的依据。
- `State`：仅描述一个原生状态的当前输入／执行上下文，可用于查看，不能自行升级成全局常量。

全图未完成时，入口 φ 的已观察值可能为 7，但尚未覆盖的输入仍可能携带其他值。该观测保留为 State 事实，不能用于把 φ 或消费者改成无条件常量。与此同时，当前有效且已完成的 `2 + 3` 不依赖开放输入，仍能证明为 Definition 常量 5。

事实有效性与数值精度分别表达。已采集但为 Top，与没有采集、未执行或回执过期不同。有限候选集合为 Top 时，也可能仍有区间、已知位、同余或非零性质；精确常量查询使用所有数值组件。

Web 点击 SSA 的 `%value` 可打开 **SSA value** 检查器，查看定义位置、变换规则、各自带 scope/status 的事实，以及候选、区间和已知位等性质。**Go to source** 按原生状态和 PC 跳转。切换查看的值不会重新运行分析；新报告使用自己的 ValueId 和事实。

## 连续编号与来源关系

最终编号是 `0…value_count-1`，只在本报告内有意义。编号变化时，指令、φ、各帧出口栈、转移、事实和映射一起更新。连续编号不承诺不同报告中同号的值相同。

- 原定义位置与构建阶段的原 ValueId 说明值从哪里产生。
- `equivalent` 保存确证相等的最终值，例如 COPY 的源值。
- `dependencies` 保存原计算使用的最终值，即使操作已折成常量，这些计算依据也保留。

`2 + 3 = 5` 中，2 和 3 是 5 的计算来源，不是 5 的等价值。来源元数据不要求维护第二份 SSA，也不将旧显示编号固定为永久身份。

## 文本、JSON 与共享协议

`ssa`、`analyze --ssa` 和 `explain` 使用同一个规范化核心；完整与允许的部分输出沿用各入口的覆盖约定和退出码。单程序文本在能完整对应实际执行的字节码块时继续使用 `σᵖ` 标签；原生执行没有对应字节码块或涉及额外机器状态时使用原生标签，并提供状态映射。预编译等无字节码执行不会借输入程序的块编号制造 PC。

CLI JSON 的 `ssa` 或 `partial_ssa` 包含 `facts` 和 `mappings`。指令的 `pc/opcode/immediate/operands/results/fault` 是原执行来源，`operation` 是规范化计算；阶段与效果仍保留。单程序 JSON 同时提供 `machine_analysis` 与 `state_mapping`，连接原生 SSA 和投影 CFG。

Web 协议版本 6 引入了这些字段；当前共享协议为版本 9，`ssa.values` 按最终 ID 索引，将定义的来源、变换、等价关系、计算依赖和多项 scoped facts 放在一起；每条指令增加 typed `operation`。[协议类型](../crates/evm-abstract-protocol/src/ssa/values.rs)。
