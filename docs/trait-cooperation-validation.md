## Semantic acceptance boundaries

- Composition uses explicit typed routes and registered sound reductions. Client authors own the semantic laws for their facts, joins, widening, equivalence and work quotations; Rust checks types and permissions and supplies no automatic proof of arbitrary client rules.
- Descending feedback is scoped to one immutable input generation. Production feedback currently constrains active stack slots on detached execution views. Global joins continue to cover incoming alternatives; a wider input requires fresh facts and tasks. Arbitrary dynamic plugins and general fact retraction are outside the current interface.
- The generic kernel accounts for dependencies and obligations. Production unknown-world effects, recursive semantics, semantic rollback and correlated state coverage remain EVM adapter responsibilities. Conservative control-flow edges follow those adapter rules.
- Local precision limits, resource refusal, runtime interruption and semantic closure have distinct meanings. `Closure::Closed` requires all mandatory obligations to be discharged; an arbitrary resource cutoff can leave detailed execution `Incomplete` or return a typed cooperation error. Current tests do not establish closed coverage for every cutoff or program.
- Optional `AllInputStates` root-terminal coverage has its own original-input and session identity requirements. It does not complete the detailed CFG or SSA. The ad-hoc cooperating resource case lacks AnalysisSession snapshot/revision, so it explicitly retains no coverage attachment even when enabled. [Session root-coverage regressions](../crates/evm-abstract/tests/root_terminal_coverage.rs) exercise their separate contract.

Read results at each delivery boundary: native exit or external termination, detailed status/frontiers and pending work, summary inputs/outputs and closed flags, optional root coverage, and report/consumer validation. Native exit 2 accompanies an Incomplete report. Preserve a whole-report guard rejection and any streaming supplement as separate observations.

## Remaining integration and replay acceptance

The final integration owner must record the complete local Nix gate on a clean commit synchronized with latest main, including its full SHA, main baseline, exact command and actual exit code. Native delivery, matching Wasm/Web assets, real browser checks, feature variants and no-dynamic-dispatch checks belong to that gate. Verify the [cache-boundary probe](../scripts/check_cache_boundaries.json), including the new kernel package's actual dependency boundaries. New commits require fresh final verification under [the local merge process](local-ci.md). The standalone complete small-language interpreter witness also awaits source-bound completed validation. These obligations remain open in this record.

Controlled baseline/candidate A/B replay is pending. Bind each executable to its complete source SHA/tree, clean state, actual Nix derivation/output and ELF hash. Reusing an existing output requires an identical pinned derivation and its producer receipt. Retain immutable input bytes, code identities, snapshot/environment/fact boundaries, complete policy, argv, resource samples, outputs and harness hashes.

Use the [fixed offline corpus](../examples/no-smt-scale/README.md), preserving unknown caller, call value, calldata content/length and unobserved accounts/storage. The [captured USDC witness](../examples/known-recursion/README.md) supplies a separate call/delegatecall and rollback input. WETH/USDC replay uses the fixed observed worlds without live RPC hydration.

Record two separately named policies:

1. Current CLI policy: explicit `max_work=2000000000`, `root_terminal_coverage=true` and all remaining current defaults.
2. Fixed high-budget policy: explicit `max_work=1000000000000`, `root_terminal_coverage=false`, original corpus guards and remaining limits.

The [command generator](../scripts/generate-no-smt-scale-commands.py) produces the fixed policy; deriving the current CLI policy changes those two reviewed fields. The [guarded runner](../scripts/benchmark-no-smt-scale.py) preserves normal exits, external stops and whole-report guard failures.

A performance conclusion requires interleaved paired runs of frozen baseline/candidate ELFs under identical inputs, policies, resource controls and delivery boundaries, without concurrent task builds. Compare elapsed time and peak RSS alongside semantic precision, closure and output size. Retain the work-accounting version; different versions use different units. A single screen establishes reproducibility only.

Strict semantic comparison retains every semantic field. The [identity normalizer](../scripts/normalize_identity_scopes.py) permits consistent bijective renaming of supported `identity_scope` namespaces. Changes to aliases, source relationships, counters, diagnostics or ordering require visible review.
