# 04：给流动的栈值起名字

本课目标：能解释 φ 的边语义，手工追踪 DUP/SWAP，并指出循环 SSA 的有限表示。

## 位置会变，值的来源不会变

EVM 每条指令围绕“栈顶第几个槽位”操作，追踪数据依赖很麻烦。SSA 为每个静态定义分配唯一名字：

```text
%a = PUSH1 2
%b = PUSH1 3
%c = ADD %b %a
```

这里的字母只是讲解用；CLI 使用连续的 `%0`、`%1` 等编号。后续使用直接指向定义。一个静态定义在循环中可以执行很多次；“单赋值”说的是程序里只有一个定义位置，不是运行时只计算一次。

## DUP 和 SWAP 不是重新计算一个数

```text
PUSH 1  : [%a]
DUP1    : [%a, %a]
PUSH 2  : [%a, %a, %b]
SWAP1   : [%a, %b, %a]
```

只有两个定义。DUP 把同一个名字再放一个槽位，SWAP 交换引用。如果每次 DUP 都制造一个“未知新值”，原来的数据依赖关系就丢了。

运行：

```bash
cargo run --locked -p evm-abstract-cli -- ssa --hex 60018060029000
```

观察 `values=2` 和出栈 `[%0, %1, %0]`。

## φ 按前驱选值，join 则合并信息

diamond 的两条前驱分别带来一个值：

```text
left:  %left  = PUSH 2
right: %right = PUSH 1
merge: %x = phi(left: %left, right: %right)
       %ten = PUSH 10
       %sum = ADD %ten %x
```

运行时从 left 进入，φ 选择 `%left`；从 right 进入，选择 `%right`。φ 不把 1 和 2 相加，也不随机选择值。

抽象分析记录 `%x` 可能是 `{1,2}`；这个**集合 join** 是分析行为。**φ** 是 IR 的数据流结构。两者出现在同一个汇合点，但语义不同。

## 为什么先给入口分配名字

[`ssa/build.rs`](../crates/evm-abstract/src/ssa/build.rs) 做两阶段构建：

1. 为每个状态的每个入栈槽位分配一个 φ 结果名字。
2. 从这些名字开始模拟本块的栈位置操作；普通输出分配新名字，DUP/SWAP 保留身份。
3. 全部块有出栈后，为每个 φ 补上前驱的对应出栈名字。

第三步可以引用尚未在线性遍历中出现的定义，因为分配和连边分开了。循环不会迫使我们无限展开。

因为 φ 先分配，输出里的 `%0` 可能在最后的汇合块定义，而第一条 PUSH 得到 `%1`。编号只表示唯一身份，不保证等于源指令顺序。

```text
entry: %zero = PUSH 0
head:  %i = phi(entry: %zero, head: %next)
       %one = PUSH 1
       %next = ADD %one %i
       ... 决定是否跳回 head
```

静态图里 `%i`、`%next` 有有限定义位置；运行时它们代表不同迭代产生的值。φ 选择上一次经过回边时携带的 `%next`。

## 为什么保留单前驱 φ

这个教学版本为所有入栈槽位分配块参数，单前驱也显示 φ。它是合法而非最小 SSA，牺牲简洁换取局部、可检查的构建过程。

可以之后实现 trivial-φ 消除：如果所有非自身输入都来自同一个值，将 φ 替换为那个值并更新 uses。环状 φ 不能用递归替换草率处理。经典的 dominance frontier 插入是另一种路线，并非构建 SSA 的唯一方式。

## 验证器在检查什么

[`ssa/verify.rs`](../crates/evm-abstract/src/ssa/verify.rs) 使用 petgraph 的 dominator 算法。

块 A **支配** B，意思是从入口到 B 的每条路径都经过 A。普通 use 的定义必须支配它；同一个块中必须先定义后使用。φ 的输入发生在前驱边上，所以定义要支配**前驱的出口**，不必支配当前汇合块。

验证器还检查值 ID 连续且只定义一次、块数/身份/访问 pc 与分析一致、入出栈高一致、φ 恰好覆盖每个不同前驱、φ 输入等于那个前驱的真实出栈槽位。

如果同一对节点同时有 true 和 false 边，两条边携带相同出栈。φ 按前驱节点去重。若未来加入每条边不同的数据假设，这个表示就需要扩展到真正的 edge identity。

## 栈 SSA 的边界

MSTORE/SSTORE/LOG/CALL 等指令保留为顺序操作，有它们的参数与可见输出，但**没有给 memory/storage 状态分配 SSA token**。不可以据此任意重排或删除副作用。内存 SSA、storage alias 和跨调用副作用是后续课程的主题。

SSA 验证说明这个 IR 的定义与控制边结构成立；它不是整个 EVM 语义的形式证明，也不表示 CFG 精确。下一课研究用状态划分提高精度。
