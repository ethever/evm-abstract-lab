# 07：把知识变成实验

每个练习先预测输出，再运行，再看源码。答案提示不替代自己的手算。

## 1. 在十六进制里找出真 JUMPDEST

分析 `605b005b00`。列出所有指令 pc、块起点、合法跳转地址和可达状态。

<details><summary>提示与验收</summary>

pc=0 是 PUSH1 0x5b，pc=2 是 STOP，pc=3 才是真正 JUMPDEST，pc=4 是 STOP。解码两个块；从入口只访问第一个。验收时同时检查 disasm 与 CFG，避免只验证合法目标集合。

</details>

## 2. 一字节变化为什么影响结果

比较 `6002600303` 与 `6003600203` 的出栈。把 SUB 换成 DIV 再预测。为什么源码里是 `a-b`，却不能按压栈顺序来代入？

<details><summary>提示与验收</summary>

前者 SUB 得到 1，后者得到 U256::MAX；DIV 分别是 3/2=1 和 2/3=0。`args[0]` 是先弹出的栈顶。给自己的修改加一个与 revm 的独立对照，防止两边都写错顺序。

</details>

## 3. 改集合容量

运行 diamond 的 `--max-constants 1` 和 `2`。预测 pc=0e 的入栈以及 ADD 后的结果。增大容量为什么通常能提高精度，又为什么无法恢复槽位间的配对关系？

<details><summary>提示与验收</summary>

容量 1 时 `{1} ⊔ {2}=⊤`，加 10 后仍为 Top；容量 2 时得到 `{1,2}` 与 `{11,12}`。非关系域仍会生成不存在的跨槽位组合。

</details>

## 4. 在未知跳转后面放副作用

运行 dynamic-jump，定位 pc=9 的 SSTORE。根据 calldata 末字节为 4 手算具体路径。将末尾块再复制一个 JUMPDEST，预测 Top 跳转的边数。

<details><summary>提示与验收</summary>

目标未知也不能丢失 pc=4 的正常路径。每一个真实 JUMPDEST 都应是潜在后继；PUSH 数据中的 5b 不算。SSA 中必须保留 SSTORE 的参数，而不是仅保留有返回值的指令。

</details>

## 5. 观察上下文失忆

对 internal-calls 比较 k=0、1、2。然后在 helper 中增加一个条件跳转，再比较返回地址集合。为什么 k=1 可能忘掉调用来源？

<details><summary>提示与验收</summary>

每次 JUMP/JUMPI 更新有限来源历史。新的 helper 分支可能覆盖 k=1 的调用来源；k=2 可能保留更久。不要只比较状态数，要检查对应 helper 的具体上下文、返回值集合与边，并继续用 revm 轨迹验证覆盖。

</details>

## 6. 删除单前驱 φ

实现一个返回新 SSA 的优化，消除只有一个有效来源的 φ，但保持所有 uses 与 exit_stack 同步。先限定无环、单前驱案例，再处理 φ 的自引用。

<details><summary>提示与验收</summary>

建立 ValueId 替换映射，处理传递替换；单纯删除 phi 会留下未定义 use。现有 verifier 假设每个入栈槽位都有 φ，若改用别名入口参数，需要一起设计并调整表示与验证。验收包括循环不能无限递归、优化前后具体结果一致、每个 use 仍被唯一定义支配。

</details>

## 7. 给分支添加假设

设计 true 分支里 `x==5` 如何收窄 x。哪些信息需要从 EQ 的结果追溯到原值？仅保存 `{0,1}` 够不够？

<details><summary>提示与验收</summary>

需要原值身份与谓词关系，例如基于 SSA 的假设或额外约束域。仅有条件结果集合不能告诉分析器哪个槽位应收窄。添加前后都验证 coverage；不能把未知条件猜成真或假。

</details>

## 8. 用固定 storage 快照提高精度

设计 SLOAD 常量事实的输入格式，再分析 SSTORE 后的读取。先支持固定槽位，随后讨论符号槽位与可能别名。

<details><summary>提示与验收</summary>

输入应标记链、block hash 与假设。固定地址可以强更新；未知地址写入可能需要弱更新/失效相关摘要。验收必须包含“写入前读到初始值、写入后读到新值、未知别名不继续使用旧常量”的反例。

</details>

## 9. 把证明义务写在边上

为每条 edge 加上解释：它来自常量目标、有限集合、Top 目标还是条件分支。实现一个命令查询某个 SSTORE 是通过哪些抽象边可达。

<details><summary>提示与验收</summary>

边的存在不是路径可满足性证明。查询结果应保留 UnknownJump、上下文与 Incomplete 前沿，不把图可达性写成“这笔交易一定成功”。用动态跳转例子检查解释没有遗漏精度来源。

</details>
