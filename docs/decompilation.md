# 本地反编译与转换追踪

反编译入口从 runtime bytecode 和明确的 EVM fork 出发，恢复当前程序的控制流与数据流，生成保留 EVM 原语的结构化表示。它有自己的任务、IR、阶段和完成状态，不要求先运行 world 分析。

例如，未知的 storage 读取仍可表示为：

```text
x = evm.sload(slot)
y = add256(x, 1)
```

分析不必知道 x 的实际值，仍然能保留计算关系。外部调用同样保留为带返回值和效果的原语；本地分析必须保守处理调用后的 memory、storage、transient storage 和 returndata。生成表示与推导数值事实承担不同职责。

## 从命令行运行

```bash
nix run . -- decompile --hex 600260030100
nix run . -- decompile --hex 600260030100 --format json
nix run . -- decompile --file examples/diamond.hex --fork osaka
nix run . -- decompile --file examples/diamond.hex --strategy code-duplication
nix run . -- decompile --file examples/diamond.hex --execution-domain ethereum-transactions
```

默认不可约控制流策略为 `dispatcher`；`code-duplication` 显式选择代码复制。JSON 保留基线 IR、转换阶段、验证结果、诊断和来源关系。完整本地结果返回退出码 0；部分恢复或预算限制等非完整结果保留可检查的产物并返回退出码 2。输入格式错误通过普通 CLI 错误边界报告。

执行域默认是 `generic`，不增加交易资源前提。显式选择 `--execution-domain ethereum-transactions`，或 Web 的 `Ethereum valid transactions`，表示只对有效 Ethereum 区块中的交易及其内部调用提出语义等价声明；这不会查询或验证某笔交易。该域从已支持 fork 的共识 gas 上限、内存成本和 precompile 输出规则推导返回数据长度上界。配置、每个 IR 快照及实际使用该域的载荷证书都保留域和 fork 限定，文本与复制结果也注明适用范围；移植或删除限定必须重新验证。工作预算和测试 host 的内存限制不参与这项推导。详见[执行域及返回数据上界证明](decompile-execution-domains.md)。

内存关系分析同时改进无符号 AND 的上界传播，以及固定地址单元在无环合流和外部循环入口处的区间合并。不同路径的值不被当作同一个常量：新的内容身份绑定到内存版本和单元地址；循环内部变化的值不能因此获得跨迭代不变身份。这些通用规则在两个执行域都使用，缺少合法尺寸或无回绕证明时仍保留原始内存操作。

工作量、块、值、复制数量、历史保留和结构深度有独立的配置边界，使用 `decompile --help` 查看参数。历史保留按阶段、引用和来源记录的保守单位计费，不等于唯一节点数量。达到预算不能当作已经收敛；任务生命周期结束也不等于控制流已经完整恢复。

反编译资源预算默认采用 `u64::MAX`，即 **18446744073709551615**。共享默认值同时用于前端、CLI 和服务端：

| 配置 | 默认值 |
| --- | --- |
| bytecode、blocks、operations、values、work、iterations、clones、history 上限 | `u64::MAX` |
| 结构递归深度 `max_structuring_depth` | 实现支持的最大值 `512` |
| 有限常量集合容量 `max_constant_set` | `8`，约束组合数值域中的有限集合组件 |

最大预算只表示允许额度，不会按该数值预分配内存。可以显式设置更小的预算，工作量为零、超限、取消及未完成状态仍按原有规则报告。请求大小、序列化结构、EVM 栈和结构递归的独立硬边界仍然有效。

预算配置、进度和统计采用固定宽度 `u64`，通过 JSON 数字保留完整值；32 位 Wasm 前端用 Rust serde 直接解析响应文本。预算编辑器保留十进制文本并精确解析，支持大于 `2³²` 和 `2⁵³` 的整数。空白、负数、小数或超过 `u64::MAX` 的草稿会显示错误并禁止按钮和 Ctrl+Enter 提交，直到修正；不会偷偷发送上一次有效数值。

执行器的集合索引和内部工作账本仍使用本机宽度，在需要时做受检转换。若某个平台无法表示请求的工作量或常量容量，返回带字段和值的明确拒绝，并保留原始配置；不会截断或静默缩小预算。文本导出的公开额度、已用工作量和进度回调也使用 `u64`。旧的小整数配置仍可读取，显式配置的产物身份不变；默认配置改变会自然产生新的配置身份。

如果只保留了解码阶段，输出应明确展示原始指令及“未恢复”的状态；缺少栈输入的指令不能显示成已经恢复出的正常计算或写入。部分恢复的 CFG／SSA 与仅完成解码是不同状态。

## 恢复中的共享数值与路径分析

恢复器直接使用独立 `evm-domain` crate 的 `ProductAlgebra`、`EvmValue` 和 `RelationState`。数值状态同时保存有限候选、已知位、有符号／无符号区间和同余约束，符号表达式与路径保证负责跨值推理。它不调用 `evm-abstract` 的执行引擎，也不依赖其机器状态、RPC 输入或报告类型。现有的返回地址上下文划分和 CFG 固定点继续由反编译器管理。

私有执行状态与公开 IR 的 `ValueFact` 分开。前者保留组合域和路径信息，后者仍是跨所有已分析访问的有限候选上界或 `Unknown`。发布摘要不会反过来覆盖更精确的当前路径状态；某个公开值显示 `Unknown`，不表示内部没有范围或关系证据。

例如，下面两个分支都可以在恢复阶段证明不可达：

```text
x = evm.callvalue()
if (x < 10) {
    if (x >= 10) { evm.sstore(0, 1) }
}

if ((x & 0xff) > 0xff) { evm.sstore(0, 1) }
```

`JUMPI` 的真假边分别加入条件假设；只有数值域或关系分析证明矛盾时才省略边。跳转目标也在选中边的条件下重新查询，因此条件能够把原本未知的计算目标收紧到合法 `JUMPDEST`。候选样本、查询未完成和表达式保留限制都不能作为目标集合完整或路径不可达的证据。未知出口仍保留 `unresolved`，开放 CFG 的事实继续受 `FactScope` 限制。

本地内存保存确定地址上的整字事实，并可通过相同的可信符号地址转发写后读。合流逐地址合并值：两条路径分别写入 `7` 和 `9`，后续读取可以保留 `{7,9}`；确定未写过的具体范围仍为零。未知地址或可能重叠的写入使受影响事实失效，字节写入不被误当作保持整字不变。持久和瞬态存储采用同样保守的本地写后读规则；入口存储均未知，因为 runtime 可以在同一交易中被再次调用。可能通过回调改变存储的调用和创建操作使相应事实失效。

这些优化依赖以下不变量：

- 每个保留的值是当前路径所有具体值的上界，纯运算遵守 Word256 回绕和 signed／unsigned 区别。
- 只有不可变帧输入具有跨块稳定身份。`GAS`、`MSIZE`、调用结果、返回数据和存储读取不会因复用了一个 SSA 编号而被认作同一个动态值。临时定义身份在跨边时清除。
- 合流保留共有路径保证并合并数值。无环的多路合流只执行 join；只有新边闭合已发现的上下文回路时，才把对应入口标为 widening 反馈点。有限候选仍完整时，逐个核对成员并用共享常量与合流操作等价地规范化数值部分，保留有限周期的精度；超过集合容量后才使用共享扩大策略。每个已发现的回路都包含反馈点；不同内部返回上下文不因原始 PC 相同而混合。路径内细化只修改执行副本，不能缩回已经保存的扩大锚点。
- 可选推理失败保留原上界和可能路径。累计工作拒绝或取消通过原有未完成边界结束，不把部分计算发布成已完成证明。
- 本地读写事实只在对应状态版本内有效，调用、未知别名和合流不能把某条路径的存储值升级为全局常量。

有限规范化要求候选集合完整：逐一检查有限候选是否满足已知位、区间、同余等全部组件，得到的就是该数值抽象值表示的具体集合。通过共享常量构造和数值 join 重建，只改变冗余表示，不增加任何路径假设。规范化后的集合随入口合流单调增加，其他字段由该集合确定；超过容量后转入 widening，后续普通 join 不会重新恢复有限集合而撤销已经完成的扩大。

上述范围不是完整的跨合约执行或通用符号堆恢复。不能证明的别名、动态字节构造和外部调用结果仍保留原语；后续错误载荷的仿射关系与循环归纳证明继续通过各自证书检查。复用共享域并不意味着直接使用某个链上快照的事实作无条件反编译结论。

[精度回归](../crates/evm-decompile/tests/precision.rs)将原始字节码执行与各阶段的 SSA／结构化执行对照，检查终结、可观察效果、最终状态，以及每次循环访问的具体值是否落在公开事实内。它同时覆盖可删路径和必须保留的反例；测试用于发现实现错误，上面的局部语义不变量仍是审查依据。

## 两种不可约控制流策略

考虑入口既能跳向 A，也能跳向 B，而 A 和 B 形成循环的情况。已知这些边之后，图仍可能没有唯一的循环入口。这是结构化问题，与尚未知道某个 JUMP 目标的问题分开处理。

`dispatcher` 为需要处理的区域引入辅助状态变量、分派和循环控制。辅助变量属于生成的 IR，不表示原合约存在对应的 storage。新增控制必须保留每条原路径上的操作顺序和参数传递。

`code-duplication` 复制选定区域，并重定向部分入口，使控制流能够进一步结构化。副本的块、值和边拥有自己的身份，仍能追溯到原始来源。复制静态代码不允许增加同一执行路径上的 SSTORE、CALL 或 LOG 等操作次数。

不同栈形状或控制地址组合在恢复阶段产生的上下文副本，与不可约处理阶段产生的代码副本分别记录在相应转换事件中。`cloned_blocks` 统计代码复制策略发布的块，不包含恢复阶段的上下文区分。可约输入可能不需要这类复制，两种策略仍各自保留明确的配置身份。

目标不确定的间接跳转可以保留为显式未知出口，并使恢复结果标为不完整。其他已经恢复的区域仍可展示。没有恢复出的边不会被当作不可达证明。

## 结构规划、验证与规模控制

CFG 恢复与语法树构造是不同步骤。结构化先读取稳定的块、跳转边和参数传递，计算控制流事实，再生成内部结构方案；方案通过独立检查和规模准入后，才分配最终 AST 的节点身份。内部方案可以引用同一子方案，最终仍使用已有的 `If`、`While`、`Sequence`、`Indirect` 和 `Dispatcher`，不改变公开 JSON 树的所有权规则。

公共续接不能只靠“每条退出路径都必经”的全局后支配点识别。例如两臂都可能提前 REVERT，但所有继续执行的路径都进入同一存储写入块时，可以把检查留在各自分支中，把共同写入放在分支之后。失败事实使用有限、闭合的源路径证明；循环、未知目标和未闭合出口不能因为后面存在 REVERT 就被当作必然失败。提取公共续接时保留原始条件求值、失败构造和边上的同时参数赋值，不把两臂的检查提前执行。

失败路径事实先于循环出口识别计算。从 REVERT 和异常终止块出发，反向工作队列只在一个块的全部后继都已证明失败、且没有未知出口时，将该块加入集合；集合不再增长时得到这个规则的最小不动点。自然循环的原有出口规则无法确定续接时，使用这份事实吸收跨多个块的失败尾部，再尝试确定正常续接。错误构造、条件、副作用和传边仍然执行；STOP、RETURN 和普通有限的正常后续不会因此被归为失败。已有唯一非终止出口或公共续接保持在循环外，即使更远的代码最终会 REVERT，也不把整段后缀移入循环。

这里的不动点与字节码恢复的不动点回答不同问题。恢复器传播栈值、跳转目标及上下文；失败闭包在已经恢复的固定 CFG 上证明终止性质；结构器再消费这些事实选择表示。某个分析收敛只表示其既定规则不会再增加事实，不意味着后续使用者自动利用了全部结论。失败闭包只依赖源 CFG，因此先计算它再识别循环即可，不需要让表示选择反向参与恢复迭代。

循环中的公共续接还使用相对于区域边界的事实。局部查询在已确认的自然循环入口、指定 continuation 或当前循环的正常出口处停止；每个边界保留自己的源块身份，边界块仍由外围计划执行。有限性和失败性分别从这些边界及真实终结点反向计算，只有全部已知后继都满足条件的前驱才能加入闭包。正常后支配只忽略已证明失败的路径，不把 STOP、RETURN、未知跳转或剩余环当作失败。这样既能识别本轮中的共同后续，也能识别循环前汇合到同一个循环入口的路径，而无须假定整个循环最终退出。

区域事实只用于提出结构候选，不改写恢复后的 CFG，也不替代全局有限性事实。查询缓存区分 continuation 和活动循环；完整区域事实只保留一个当前上下文，集合存储与计算工作在分配前计费。事实超过存储准入时保留原有保守选择，工作量耗尽和取消仍按原有完成状态报告。

规划器提出候选；检查器独立核对候选控制骨架与原 CFG 的逐步对应，包括块体、条件选择、传边、终结、循环控制及分派转移。候选中的摘要或来源列表本身不是正确性的证明。没有通过检查的构造不能获得删掉源路径或省略状态传递的权限。

规模估算针对最终展开的节点出现次数、深度、来源引用和分派转移，不只计算内部计划图的唯一节点数。Sequence 在分配最终节点身份前扁平化，临时计划构造与最终保留规模分别约束。自然结构过度展开时，默认策略可以在明确的区域边界内使用紧凑 dispatcher；其每个 case、转移和参数赋值仍需要计量与验证。全局预算、取消、未知恢复以及无法验证的候选保持各自的完成状态，紧凑表示不把未恢复的行为标成 Complete。

临时计划回滚只撤销尚未发布的节点和相应 PlanId 缓存。源图的邻接索引、已算出的公共续点与残余环查询结果独立保存；确定没有公共续点的结果也可以复用。累计自然规划尝试和紧凑化压力不会随回滚归零，避免同一大区域反复消耗预算后重新开始。已经通过准入的自然子方案仍可复用；达到压力边界后，未缓存区域直接尝试完整源 dispatcher，无法容纳紧凑方案时仍明确拒绝。

这种规划改善的是生成表示的规模。错误字节证明、表达式简化、`require` 认证和共享过程的语义对应继续有各自的检查；识别某条路径以 REVERT 终结，不要求先还原其错误字符串。CLI 与浏览器消费同一份已经发布的结构化结果，显示开关不会重新运行结构规划。

## 阅读偏好与区域选择

阅读偏好在已经恢复的源控制流上选择表示，不能改变指令效果、原条件的求值位置、参数传递或终结行为。`balanced` 默认保留自然控制，并比较重复和显式分派的成本；`linear` 更重视主线、较浅的控制与可见状态效果；`compact` 更重视共享和减少重复表示。这些是可解释的策略，不是人类理解成本的测量，也不承诺全局最优。

默认与线性模式不会仅因原始操作重复而扩大 dispatcher 的源块覆盖：后续高层投影仍可能把这些操作整理成简洁 guard 或共享计算。紧凑模式允许这种取舍，显式区域偏好也可请求它；必须控制的表示增长与语义准入仍独立处理。

```bash
nix run . -- decompile --file contract.hex --readability linear
nix run . -- decompile --file contract.hex --procedures inline
nix run . -- decompile --file contract.hex --readability compact --procedures shared
```

`--procedures auto` 使用阅读配置比较过程定义、调用文本、跳读与参数对应成本。`linear` 的自动选择保留普通带状态依赖的区域在原位置，仍可为复杂纯计算选择有益的过程；`inline` 不采用可选过程提取；`shared` 明确偏好已经认证的共享计算。它们沿用相同的基础 Lifted 证明与可选优化事务。内联可能增加文本长度，共享也可能引入更多调用位置，不能只用过程数判断结果优劣。

前端的阅读设置与结果 Inspector 都可提交这些偏好。区域选择来自后端保留的决策：可以对某个源区域选择自动、偏好自然结构或偏好 dispatcher，并用原始字节码和恢复配置重新分析。Inspector 展示实际选择、原因和已测量候选的控制嵌套、源操作出现次数、重复及分派成本。源操作统计包含栈操作，不能当作最终可见代码行数；失败分支的深度折扣只用于已有有限失败证明的情况。候选成本不构成正确性证书，最终选择仍经过独立的源控制对应检查。

产物 schema 9 将 dispatcher 原因绑定到实际触发位置：`residual_cycle` 表示仍有未纳入自然循环的环，`control_reentry` 表示构造再次访问当前路径上的块，`validation_fallback` 表示候选没有通过控制验证而采用已验证的分派方案。它们都不单独证明控制流不可约或具有多个入口。规划准入、深度、展开、阅读成本和用户偏好分别保留各自原因。旧产物的 `multi_entry_control` 仍可读取，但界面明确说明其详细原因不可用，不据此宣称多入口；旧 schema 不能冒充携带新增原因的产物。

区域身份包含独立于阅读偏好的输入/fork/恢复配置指纹，以及完整的入口、继续位置和循环上下文。改变阅读偏好可以复用同源选择；改变代码或恢复设置时旧选择失效。单独的 PC 或 AST 数字 ID 不作为跨重跑的区域身份。无法匹配的偏好以信息诊断保留；偏好自然结构不能绕过必须保留的未知出口或表示准入，也不会静默覆盖另一套全局控制策略。

CLI 的 `--readability-config preferences.json` 接受完整的 `ReadabilityConfig` 对象：

```json
{"profile":"linear","procedures":"auto","regions":[]}
```

局部选择项使用结果中 `artifact.readability[*].region` 的完整锚点，并附加 `structure` 为 `auto`、`natural` 或 `dispatcher`。命令行显式的 `--readability` 和 `--procedures` 覆盖文件中的对应全局值。配置和决策使用产物 schema 7；旧产物省略这些字段的原有格式仍可读取，不能通过降低 schema 号冒充新偏好或决策记录。

已经认证的共享调用还可以在前端原地展开。展开恢复该调用位置的源表达式或源结构，不重新解释另一份过程体，也不改写后端产物。显示与复制使用同一投影；新产物到达时，旧展开身份不会套到碰巧复用数字 ID 的位置。这类阅读操作与要求后端重新选择结构的区域偏好分开处理。

## 内部返回地址与恢复上下文

内部调用常把返回地址保存在 EVM 栈中，再用 `JUMP` 返回。两个调用即使进入同一个 PC、栈高度也相同，其外层与内层返回地址仍然有对应关系。若分别合并每个栈槽，可能把一个调用的外层返回地址与另一个调用的内层返回地址组合起来，产生具体执行不会经过的候选边。

恢复器为 `PUSH` 引入的合法 `JUMPDEST` 字面量保留控制地址标记，随 `DUP`、`SWAP` 和块参数传递。上下文按原始块、栈高度及控制地址的组合区分，同时保留当前返回地址与外层返回地址的对应关系。这里不依赖推测的函数边界或编译器调用模式。

算术计算和 `MLOAD` 产生的值不继承这个字面量标记，仍按数值抽象恢复跳转；计算或内存中转的返回地址可能保留更宽的候选范围或未知出口。标记不随数值事实变宽而变化，普通数据循环仍使用固定点合并。上下文增长受块、操作、值、迭代和工作量预算约束，达到限制时保留先前验证过的阶段并明确报告未完成。

已知目标与未知目标进入不同上下文时，未知上下文仍可沿同一原始跳转已经发现的合法目标继续恢复，并携带自己的栈值与内存状态。后续发现的新目标会重新唤醒相关未知上下文。已知候选不代表完整目标集合，未知出口始终保留；不会为了补齐图而连接所有 `JUMPDEST`。

## 无用入口参数清理

Baseline 保留完整的入口栈和边实参，便于追踪原始栈位置。Simplified 阶段根据保留的指令操作数、控制流与退出操作数确定哪些入口参数仍有用途，并沿所有入边反向传播到固定点。只在参数之间循环传递、最终没有用途的参数也可以移除。每个目标块及所有入边使用同一位置筛选，保留参数的身份、顺序和数值事实，参数索引则重新紧密编号。

例如，某个 REVERT 块在入口接收十个旧栈值，却只使用块内新生成的偏移和长度，优化后其十项并行赋值就会消失。内存和效果入口仍然保留。`dead_block_parameters` 转换记录列出被删除的参数和改动的边；在 Changes 或历史阶段中仍可定位原参数及其来源。

未知或待恢复的跳转边界保留完整入口参数及其上游依赖。参数表变短不代表原始 EVM 栈变短，恢复阶段确认的栈溢出、下溢和其他异常继续保留。该清理不删除上游指令，因此调用、读写、日志及其依赖顺序不会因为某个入口参数无用而被移除。预算或取消中止优化时，只保留先前已经验证的快照。

## 高层表达式与简化结构化代码

`Structured` 完成控制流结构化，块内仍保留 EVM 原语。其后新增的 `Lifted` 阶段保存一份有类型的语义投影：表达式 DAG、高层语句、条件和逻辑参数传递都有独立身份及来源。该快照同时保留原先的块、边、值和结构化控制拓扑，作为执行与核对依据。

例如，输入未知时也可以用恒等关系将三重零判断压缩成无符号比较：

```text
c = lt(a, b);
x = iszero(c);
y = iszero(x);
z = iszero(y);
if (z != 0) { ... }
```

高层条件表示为 `if (a >= b) { ... }`。word 按 256 位 EVM 语义解释，普通比较符号表示无符号比较，`evm.slt`、`evm.sgt` 及其明确的逻辑否定表示有符号比较。高层区分 `Word256` 与 `Predicate`；谓词被算术、存储等 word 使用者消费时，使用明确的 `word(predicate)` 转换，结果为 0 或 1。因此，未知整数的双重 ISZERO 会保留非零判断及必要转换，不能直接替换成原整数。

表达式 DAG 的共享不代表打印时也只展开一次。高层投影按操作及子表达式计算保守展开成本；纯计算结果过大时，在原指令位置保留有名字的 SSA 语句，后续引用该结果。这样可以避免反复内联产生指数长度的表达式，不需要提高单表达式显示上限。新增绑定仍通过原有作用域、活性和语义投影检查；不会移动 memory、storage、调用或 fault，也不改变数值抽象的精度设置。

保留名字与简化右侧表达式分别处理。例如，跨块使用的结果仍需定义 `v16`，但 `v16 = evm.and(left = M, right = (M & v7));` 可以显示为 `v16 = (M & v7);`；不同常量掩码则合并为一次按位与。内联表达式与保留语句的右侧复用轻量模型中的同一套 Word256 代数规则。显示层在类型、原始指令和输入来源可核对时生成有类型的简化结果，不移动定义或再次执行 `v7` 对应的 storage/memory 读取。未满足条件的语句保留原语表示，工作或文本预算耗尽则报告限制。CLI、网页和共享过程体使用同一个格式化入口；JSON 中的原始操作、语句输入、输出身份与来源映射继续保留，因此不需要更改 wire schema。

高层默认同时使用经过认证的 `require` 和显式的失败优先 `if`。已有空 REVERT、规范 `Error(string)` 或已恢复数据的 guard 证书通过来源与作用域检查时，可显示 `require(condition);`、`require(condition, "message");`、`require(condition, Panic(0x41));` 或保留 selector 与完整 word 的错误。未获得这种证书，但共享模型证明某一分支会在有限、闭合的路径上以 REVERT 或异常终结时，将完整失败路径放入 `then`，成功路径放在外层继续执行。例如：

```text
require(okA);
require(okB, "Transfer failed");
if (!okC) {
    evm.invalid();
}
if (!okD) {
    v1 = evm.mload(offset = 0x40);
    evm.mstore(offset = v1, value = selector);
    // 其余原始错误数据构造语句保持原顺序
    evm.revert(offset = v1, size = size);
}
evm.sstore(slot = 0x0, value = 0x2a);
evm.stop();
```

显式失败分支中的 MLOAD、MSTORE、调用、环境读取与传边赋值都留在原失败路径上；REVERT 和 INVALID 保持各自的终结身份。实际执行 `0xfe` 的终结显示为 `evm.invalid();`，栈错误、非法跳转及其他 fault 仍显示各自诊断。`require` 只吸收自身证书覆盖的失败构造，不删除其他分支的构造。成功路径的多个右值仍先同时求值，再写入目标参数。条件翻转使用有类型的谓词，重复逻辑否定会规范化；256 位回绕算术和有符号比较保留，例如 `evm.slt((size - 0x4), 0x40)`，不会改写成缺少前提的整数长度比较。嵌套检查的成功路径可以依次显示在同一缩进层，条件和观察操作不会因此合并或提前执行。

有时原始结构化树将失败块放在当前 `If` 后面的 Sequence 尾部。只有该尾部属于当前显示范围、失败分支与完整尾部共同闭合为失败，且成功分支不会正常落入尾部时，表示计划才把这些原始节点一起移动到失败 `then` 中。共享过程定义使用自己的 body 作为范围；不会借用祖先 Sequence 或其他调用点的尾部。若成功分支仍会流入同一个 REVERT，例如先执行 SSTORE 再 REVERT，该共同尾部继续保留在正常续接之后。经过认证的检查可显示为：

```text
require(C);
evm.sstore(slot = 0x0, value = 0x2a);
evm.revert(offset = 0x0, size = 0x0);
```

STOP、RETURN、SELFDESTRUCT 和隐式 EOF 是正常结束；两边都有正常行为的条件继续保持普通分支。循环、dispatcher、未知出口、Partial 边界和未闭合的路径不会被当成失败证明。失败优先布局不依赖错误字节是否可识别；INVALID、未知载荷或带观察及副作用的失败体不会因此获得 `require` 证书。

高层还可独立认证由 MSTORE／MSTORE8 和固定代码源 CODECOPY 构造的规范 `Error(string)`。消息和完整 ABI 字节保留在 Inspector 中作为可导航的证书。只有选中的 `require` 计划可以吸收其失败路径上的对应构造；单独存在的构造以及仍被正常路径使用的共同尾部继续显示原始操作和 `evm.revert(offset = ..., size = ...)`。页面、复制文本、CLI 和共享过程定义使用同一份表示计划；状态依赖与结构注释开关只改变相应辅助行，失败体与成功续接的位置保持一致。

错误字符串的认证需要不同层次的证明。终结指令证书核对 REVERT 的实际 memory 版本、偏移、长度，以及完整返回字节。分析沿内存版本追踪写入，使用相对地址、范围和不重叠关系转发读取，再按最后一次写入生效恢复字节；验证器按提供的写入见证正向重放，检查 selector、ABI 偏移、字符串长度、UTF-8 内容和零填充。相同数值范围不能代替读取身份相同的证明，空闲内存指针的事实必须来自实际初始化、更新和所有相关前驱，不能靠 Solidity 习惯猜测。

CODECOPY 的代码字节来自捕获的完整运行时代码。包含这条指令的 IR 保存不可变的 `runtime_bytecode` 见证；阶段转换不能增加或替换该来源，完整产物要求它与 `Input` 一致。使用代码复制的终结证书同时保存 `code_hash`，独立重放核对原始 COPY 指令位置、来源哈希及实际切片。复制越过代码末端时按 EVM 语义补零，极大的源偏移不会回绕到代码开头。只为返回区间的相交部分提取字节，不能因为原始 COPY 很大就在证明器里分配同样大的缓冲区。这些新增字段属于 schema 10；旧产物未声明的来源不会被补猜成新证书。

动态分配还需要保留多个符号之间的关系。例如，Router02 的一条数组计算路径先分配两个长度为 `n` 的数组，再在每轮分配临时数据。相应的候选关系是：

```text
amounts_header = 0xa0 + 32*n
F_0 = 0xc0 + 64*n
F_i = F_0 + 189*i
本轮两次更新：F_i + 72，随后 F_i + 189
```

这里第二次更新仍以本轮开始的 `F_i` 为基准，两次更新合计增长 189 字节。指针不是已扩展内存大小，也不必保持 32 字节对齐。分析器从实际初始化、算术、写入和控制流提取这些关系，不识别上述常数或函数名字。路径上的成功检查提供长度上界；复合条件只按有效逻辑拆分，例如 `OR(a, b) == 0` 同时要求两个操作数为零。

循环证明把计数器、指针槽和数组长度头一起处理。候选发现与准入检查分开：先提出递推，再从所有实际入口检查初值，在假设当前轮满足不变量的临时状态中重放循环体，核对每条正常回边是否保持下一轮关系。参数在回边上同时替换。入口依赖前一个循环时，按控制流顺序重新核对其证明，不能直接信任候选发现时留下的状态。每个写入、复制和调用输出区域都必须证明不会覆盖仍要保留的内存单元。验证失败或取消时，临时候选及其推导出的事实不会进入后续字节证明。

不重叠检查需要相对地址。例如临时区与数组头的距离为 `F_i - amounts_header = 32 + 32*n + 189*i`；分别取两个地址的绝对区间会丢失共同的 `n`。但模 `2²⁵⁶` 的减法结果不能直接作为内存次序证明：`p - 1` 与 `p` 附近的写入仍可能重叠。分析分别检查模算术身份、普通整数范围及地址末端不回绕。递减计数器的 `ADD(MAX_UINT256, i)` 也只有在实际路径和归纳条件支持时，才能按有效的 `i - 1` 推理。

这些内部关系服务于已有的字节与构造证书，不增加一种前端猜测规则。失败发生在本轮分配之前或之后时，使用各自程序位置的指针；上一轮保存的指针不会因为 SSA 指令身份相同而变成本轮指针。当前归纳域要求已闭合的控制流、唯一入口 header，以及切断 header 回边后无环的循环体；递推和有限轮数必须能够得到验证。未能证明的循环、未知覆盖及超出关系域的表达式继续使用原有表示。实现见[关系分析](../crates/evm-decompile/src/lift/payloads/memory/relations.rs)，实际字节码与执行对照见[Router02 回归](../crates/evm-decompile/tests/router_error_payloads.rs)。

未显式写入的填充使用单独的内存写入上界证明。`E` 表示截至当前 memory 版本，所有已发生写入的结束地址都不超过 `E`，因此 `[E, ... )` 仍是初始零内存。只有完整、无入边、位于 PC 0 的运行时入口能建立初始 `E = 0`；读取、分配指针或 ABI 惯例不能建立这个事实。MSTORE、MSTORE8、各种复制和调用输出均更新上界；无法界定的写入使其失效。分支汇合要求每个前驱都支持界限，循环候选从真实入口及每条回边重新验证，失败的候选连同临时导出的上界一起回滚。字节验证器重新计算这些事实，不信任发现阶段留下的状态。

Router02 的这个具体构造返回 132 字节：4 字节选择器、32 字节偏移、32 字节长度、40 字节消息和 24 字节填充。令本轮开始的分配指针为 `H_i`，循环不变量证明此前写入的结束地址不超过 `H_i + 96`；两次临时分配把指针推进到 `P = H_i + 189`，调用输出最多写到 `P + 96`，三个错误头写入最多到 `P + 68`，40 字节 CODECOPY 最后写到 `P + 108`。所以 `[P + 108, P + 132)` 从未被写入，24 个字节均为零。189、96 和 108 来自实际指令及数据流，不是识别函数名或地址后套用的常数。测试中的输出区改为 160 字节、无法界定的输出长度、非零尾部和指针倒退等反例不能获得对应的零证明。

独立的构造证书仍记录原始块内的准确语句范围，用于核对内存扩展、操作顺序、终结数据和原有 fault 行为。构造证书是一段原始语句的执行见证：起止位置必须包含所认证的写入与 REVERT，全部操作须属于允许的构造指令。CODECOPY 现在属于允许的原语，其三个操作数、内存输入输出、代码来源及原始位置仍逐项检查。显示成 `require` 时，仅在失败路径执行原始构造；不能用重新编码字符串替代原来的内存扩展或复制异常。相同消息可以共享字节记录，不同路径仍各自保留构造和原始操作。终结指令的字节相等不会授权删除前面的 MLOAD、MSTORE、SSTORE、CALL、LOG 或环境观察；无关操作打断构造时，已有的字节证书仍可单独供检查。

非规范填充、错误偏移或长度、无效 UTF-8 都不获得错误字符串解释，但不会丢掉已经证明的字节。未知覆盖、不能证明的不回绕地址关系则保留原始内存切片。`CODECOPY` 留下未证明的尾部填充时不能仅凭可读消息认定标准 ABI。失败优先的控制表示与数据恢复、格式识别相互独立。

点击 `require` 或失败 `if` 可检查原条件、原始分支和相关来源。显式失败体中的构造语句及终结指令保留各自的高层选择行，并能从源指令链接返回。被 `require` 吸收的构造、载荷和终结字节证书仍可在 IR 与 Inspector 中检查；原始分支引用可导航到完整的 **Structured code**。该视图始终保留原始控制树，切换视图不会修改产物。

开发者可通过 `LiftedRenderIndex::if_plan` 检查特定 AST 出现位置选择的 `Require`、`FailureFirst` 或 `Original` 计划。计划由共享模型按真实源树计算，并由显示范围限制；页面不会自行识别终结行为。后缀省略、后缀移动和构造吸收都服从同一次计划选择，表达式格式化失败会明确显示诊断并停止本次代码遍历。`LiftedProgram.failures`、`LiftedControl.guard` 和对应构造证书共同约束 `require` 的准入；不能将旧 guard 省略路径与失败优先移动路径同时应用。

`LiftedProgram.revert_data` 保存与原始 REVERT 出现位置绑定的数据证书。它先回答“该 memory 版本的这个区间包含什么”：完整数据由常量字节、符号 word 的大端字节片段及有来源的切片组成；`Raw` 则只保留原始 memory、offset 和 size，表示尚未证明内容。每个符号引用指向原始 SSA 值，不能因为 selector 或参数形状相同就合并不同的调用路径。schema 11 增加此表示；旧 `payloads` / `reverts` 错误字符串证书仍可读取，旧版本缺失的数据不会被猜补。

整段复制另有一个无需枚举动态长度的精确规则：最近的内存写入必须就是原始 COPY，COPY 的目标地址和长度必须与 REVERT 的窗口相同。两次 RETURNDATASIZE 只有在闭合 effect 链证明它们属于同一个非循环 CALL／CREATE 出现位置时才可视为同一长度；途中出现其他写入、不同返回数据版本或开放前驱时不应用此规则。数据记录保留具体调用的返回数据来源，而不会笼统写成当前的 returndata。原 COPY 及其边界检查、原 REVERT 仍是执行见证。固定区间查询则继续要求相对地址及不回绕证明，不能用模算术差值替代内存区间关系。

格式解码单独消费这些数据。完整规范字符串可解释为 `Error(string)`；`0x4e487b71` 加一个完整 word 可解释为 `Panic(code)`；其他固定 selector 加完整 word 序列只显示 `Revert(selector = ..., words = [...])`，不猜测函数名或 word 的 ABI 类型。已知 Panic 码的中文说明依据 [Solidity 的错误码表](https://docs.soliditylang.org/en/latest/control-structures.html#panic-via-assert-and-error-via-require)，只是注释，不参与语义。无法识别格式时仍可在 Inspector 查看已恢复片段和原始来源。恢复成功不等于格式识别成功，也不等于可以收起构造。

构造与控制流认证分别决定显示计划。`constructions` 指向原始块内的确切构造区间；`require` 还要核对失败路径、参数绑定及正常续接。compact 形式以失败时执行原始构造为语义，不提前计算错误参数，不跳过原有内存扩张或首次异常。失败分支中独立的 CALLDATALOAD、SLOAD、CALL 等观察不会因错误格式被识别就被前移或吸收；不能安全绑定参数时仍显示完整失败路径。轻量模型验证引用、作用域和原始构造对应关系；核心独立遍历内存写入链，再正向按最后一次写入生效重放字节身份。验证器不调用数据发现器或依靠格式名称认可字节。

轻量读取器还会独立核对已有 guard 只能选择自身 `If` 的实际分支，以及尾部范围和成功路径的正常后继关系。记录中的 `Passed` 状态不能代替这项入口检查：自引用、指向祖先或错误范围的元数据不会进入显示计划。构造和共享过程来源校验失败时，显示端保留原始语句，入口校验拒绝安装损坏的产物。

此阶段还应用已实现的基础代数与掩码规则，并根据高层消费者重新计算逻辑入口参数和入边实参的活性。已由控制拓扑完整表达的跳转、POP 等栈整理不会单独维持高层变量的存活；仍有未知或非法目标选择的跳转会保留相应目标表达式，开放边界继续保守保留入口绑定。逻辑参数数量不代表物理 EVM 栈高度。

高层投影还会传播已证明等价的块入口参数。在完整局部 CFG 中，若所有入边最终传入同一个已定义值，并且该定义所在块是进入目标块之前的必经节点，冗余参数及对应实参可以消除。相同来源的分支合流、自引用参数及有共同外部来源的复制环也按这些条件检查；不同来源的合流、变化的循环状态、没有外部来源的复制环和开放控制流保守保留。相同的抽象数值事实不构成值身份相同的证明。

例如，`v1 = evm.sload(slot);` 后经过 `v2 = v1; v3 = v2;` 的跨块传值链，可以在证明通过后改为后续直接引用 `v1`。SLOAD 仍在原位置执行一次，即使中途写入同一 storage 槽，后续使用的仍是先前读取的值。若传播源是原本会内联的纯计算结果，则在原操作位置保留一次有名字的定义，避免后续引用没有实际定义的变量。

表达式 DAG 仍按消费块组织；跨块引用使用已经证明在入口可用的原始值身份。内存读取、调用、环境观察及其他残余操作保留有序语句和不透明结果引用，保留下来的边实参同时求值后再写入下一块参数。同块内较晚产生的值不能替代块入口参数，因此不会把上一轮循环保存的值误当成本轮重新读取的值。未使用的不透明结果可以省略其高层绑定，但产生它的操作和既有 fault 仍保留。被消除的参数和实参仍通过保留的传边见证记录直接来源，底层参数表与指令不变。

`Lifted` 对应检查验证类型、DAG 引用和作用域，并检查复制方程的外部来源、入口支配关系、实际高层定义及操作顺序，再按原始见证重建规范投影核对语句、控制操作数及参数传递。重建一致性不等同于独立的通用等价证明；规则的语义还通过边界值、反例和独立高层绑定解释器与原始执行对照。复制分析、支配计算和验证计入工作预算，取消或预算不足时不发布半成品。原先逐原语的执行与验证继续适用于保留的底层见证。分析完成、提升覆盖与文本导出完成分别表达，未应用某条优化不意味着控制流未恢复完成。

前端默认提供 **Simplified structured code**，并保留 **Structured code** 查看底层结构化表示。高层实体可以在 IR、Changes 和转换检查器中检查，并回到原始指令；反向的 source descendant 导航也保留。CLI 文本默认导出最后验证的高层阶段，JSON 保存所有阶段及类型化投影。

高级表示还可以把重复且可验证等价的结构化区域提取为共享过程。定义出现在主代码之前，原来的每个位置显示独立调用。例如，下面是参数和结果传递的示意：

```text
procedure shared_42(v1, v2) -> (v3) {
    ...
    yield (v3);
}
(v100) = shared_42(v10, v20);
(v101) = shared_42(v11, v21);
```

`shared_42` 是产物内的过程身份。过程体只显示一次，每次调用仍独立执行，并产生自己的结果。`yield` 把结果交回当前调用位置。准入检查禁止过程体包含 EVM RETURN、REVERT、STOP、显式异常终止、SELFDESTRUCT、外部调用和合约创建，也禁止逃向调用者的控制转移；这些行为在外层保持可见。过程内部允许闭合的条件和循环，不要求证明循环终止。这里的共享调用不产生额外的 EVM CALL、调用帧或 gas 操作，不缓存结果，也不授权重排求值或改变原有资源观察。

候选发现寻找有实际缩减收益的重复区域；哈希、源 PC 或相似文本不能直接授权共享。检查器根据实际源区域，核对归一化表达式、保留指令、分支与循环、同时赋值、参数、结果和状态接口之间的对应关系。区域外计算的条件及其他自由值必须在调用入口可用；区域内传边才定义的值不能提前作为实参。每个正常出口需要提供对应的活跃结果，终止路径则传播原来的终止行为。memory/effect 依赖保存在类型化接口中，显示状态依赖时可以查看。

基础 `Lifted` 投影仍由原有验证器检查；共享检查证明新定义和调用相对于该基础投影的对应关系。提交一份共享计划不允许顺带修改基础表达式、guard 或构造器。guard 证书中的拥有者、后缀范围和错误构造范围也随实际出现位置核对；每个共享过程体在自身范围内选择混合表示计划，不能把一个调用位置的事实用于另一个位置。

当前共享层保留完整的 CFG、Structured 和基础高层见证。`LiftedProgram.procedures` 引用规范过程体，`invocations` 保存实际出现位置、边界和稀疏对应关系；原始代码不会在每条调用记录里再复制一份。过程定义和调用有独立来源与检查器入口，非规范调用位置中被收起的操作仍可回到原始 IR 查看。轻量读取器会检查共享记录和源接口；无效的计划不会获得省略原代码的权限。

共享分析采用有界的结构化区域和纯表达式 DAG。定义可以调用严格内部的其他过程；独立验证器检查定义依赖图没有递归环，这与过程体内部可以包含循环是两回事。无法证明的接口、逃出区域的外层循环控制，以及不支持的间接或分派区域保留原表示；分派中的独立纯表达式仍可提取。候选、对应关系、活性分析、验证、历史和文本导出都计入资源预算；取消或超限不发布半份共享层。该层改善高层代码的组织，恢复阶段的上下文区分和原始历史仍然保留。

`pure_arithmetic_N` 是经过验证的纯算术类别，可以引用表达式 DAG，也可以引用带内部循环的纯算术区域。表达式模板以有类型的叶子作为参数，包括常量，因此相同运算结构的不同系数可以共享；两个参数可以接收同一个实参，而独立的内部定义不能借此合并。原位置的 memory、storage、环境读取先产生值，再作为参数传入。Word256 回绕、有符号关系、除零和移位规则沿用既有 EVM 表达式语义。较长的单次计算也可以提取，避免把重复子项全部内联到一行。

候选指纹基于规范高层语义，PUSH 编码宽度和 SSA 编号不作为区别。指纹只减少候选比较，参数代入、接口与控制边界仍由独立检查器验证。表达式形状在一次拓扑遍历中缓存，嵌套定义引用原有实体，验证和展示不递归复制源代码。

产物 schema 6 为过程增加显式 `kind` 契约。历史 schema 5 中缺少该字段的记录按 `legacy` 解码并保持原序列化形状；它们不能冒充新的过程契约，读取器保留基础源表示。新契约不能通过把版本号改成旧版本来绕过检查。

基础高层投影与可选共享优化分别准入。首先准备一份已完成验证、来源记录及实际工作付款的基础 Lifted 发布事务，但尚不安装为当前结果；共享候选在同一累计账本的剩余额度内尝试。局部工作、保留集合或候选历史容量拒绝时，丢弃候选并一次性发布基础结果，以信息诊断 `OptimizationRefused` 说明共享优化未采用，不改变已有恢复覆盖。它不表示已经验证的原语或控制流被截断。无效的基础见证、全局必需工作拒绝和取消仍通过原来的失败边界处理，不能被可选优化回退吞掉。

接受共享候选前仍需独立核对源接口，并准备完整的候选发布事务；最终只消费一个绑定原始阶段和实际 IR 的事务。准备过程中不提前安装阶段、历史或来源表，也不通过忽略停止状态强行提交。共享容量诊断区分读取集合、控制事件、活性槽位、定义对应域和记录数量，便于判断具体拒绝发生在哪里。

仓库固定的 Router02 fixture 覆盖共享定义、多个调用位置及多块过程体，原有终结载荷与构造证书继续保留。高层表示的组织不删除原始 CFG、Structured 树或历史。检查规则见[共享来源验证](../crates/evm-decompile-model/src/shared/source.rs)，实际执行与缩减回归见[Router 共享测试](../crates/evm-decompile/tests/shared_procedures/router.rs)。

普通高级代码、共享过程、Inspector 与 CLI 的 EVM 调用统一使用 `evm.` 前缀，包括函数形式的字运算和有符号比较。位取反显示为 `evm.not(...)`，逻辑否定仍使用 `!`；`word(...)` 和共享过程调用保留高级构造的写法。失败体中的原始内存范围终结显示为 `evm.revert(offset = …, size = …)`；已认证的消息在 Inspector 的载荷证书中查看。

高层代码按 opcode 统一选择运算符或调用形式。ADD、SUB、MUL、无符号 DIV/MOD、EXP、AND、OR、XOR、NOT、SHL、SHR 分别显示为 `+`、`-`、`*`、`/`、`%`、`**`、`&`、`|`、`^`、`~`、`<<`、`>>`；位移写成 `value << shift` 或 `value >> shift`。这套规则同时用于独立 SSA 赋值、内联表达式和共享过程体。例如，保留的 `v20 = evm.add(left = v17, right = 0xa4);` 显示为 `v20 = (v17 + 0xa4);`，结果变量和计算位置仍由原语句确定。

以下 26 条指令始终使用完整命名参数：CALLDATALOAD、CALLDATACOPY、CODECOPY、EXTCODECOPY、RETURNDATACOPY、MLOAD、MSTORE、MSTORE8、SLOAD、SSTORE、TLOAD、TSTORE、MCOPY、LOG0–LOG4、CREATE、CREATE2、CALL、CALLCODE、DELEGATECALL、STATICCALL、RETURN、REVERT。例如：

```text
v4210 = evm.call(gas = (v4205 - 0x2c6), target = v4066, value = 0x0, input_offset = v4169, input_size = 0x84, output_offset = v4169, output_size = 0x0);
evm.calldatacopy(memory_offset = 0x0, calldata_offset = 0x4, size = v12);
evm.revert(offset = 0x0, size = v13);
```

CALL/CALLCODE 显示 `value` 参数，DELEGATECALL/STATICCALL 的六项参数中没有这一项；输出大小为零时仍显示原有输出偏移。创建操作区分 init code 的偏移、长度和 CREATE2 的 salt，LOG 的 topic 按原始弹栈顺序编号。CALLDATALOAD 和 MLOAD 始终使用 `offset`；复制操作区分来源与目标偏移，storage 和 transient storage 使用 `slot`。其他调用采用位置参数，例如 `evm.keccak256(p, n)`、`evm.balance(a)`、`evm.selfdestruct(a)`；无参数原语保留原有写法。运算符和命名参数都要求 opcode 与实参数量精确匹配；未知或异常数量的参数完整地按位置显示。

这些符号继续表示 EVM 的 Word256 运算，包括溢出回绕及无符号除零、模零返回零。SDIV、SMOD、SLT、SGT、SAR 保留不同于无符号运算的函数名，并使用位置参数；合成的 SLE、SGE 同样处理。ADDMOD、MULMOD 保留专门调用，表示完整精度中间结果取模。比较和 ISZERO 在条件中使用布尔形式，作为数值使用时保留 `word(predicate)` 的零／一编码。参数显示策略不会改变已有的 `require` 认证、失败分支或栈操作消除规则。

页面、复制文本、语义 Inspector 和 CLI 高层导出共用这套格式化规则，保持单行代码布局、变量身份、参数值及顺序。原始 Structured 和原始操作数视图继续提供位置参数；JSON 中的操作数和语义投影不因显示名字而改变。格式化工作量与长度限制计入新增名字和分隔符，取消或拒绝时不会把半个调用作为完整结果输出。

高层代码默认隐藏独立的 memory/effect token 传递行及语句尾部的状态依赖注释。开启 **Show state dependencies** 可显示当前投影保留的状态依赖；复制按钮使用当前显示选项，缩进与有效 word 参数传递保持一致。内存构造操作、storage、调用、日志和终止行为继续显示。该偏好在切换视图、阶段和接收新产物时保留，原始 Structured、IR 与 Inspector 始终保留完整依赖；隐藏的空传边实体仍可通过来源链接定位到 IR。切换显示不会重跑分析、创建转换事件或修改产物，CLI 与 JSON 的既有导出策略也不受这个前端偏好影响。

高层代码还默认隐藏 `// sequence ast…`、`// b… source…` 和 dispatcher 的 `// on e…` 结构位置注释。独立的 **Show structure annotations** 开关可以恢复这些上下文行；fault、未解析目标和其他诊断始终保留。两个显示偏好都影响复制文本，并在阶段、视图和产物切换后保留。隐藏的高层块标题可通过来源链接在 IR 中检查，原始 AST 节点仍导航到完整的 Structured 视图。注释隐藏只作用于前端；跨块复制消除属于共享 Lifted 投影，因此 CLI 和 JSON 也能看到参数与实参的精简结果。

普通高层分支在格式化文本之前，由共享模型对选定投影做一次有界后序规划。只有 then 有内容时省略 else；只有 else 有内容时，对有类型的条件取逻辑补集，并把完整的原 else 显示为单臂 then。两臂都有内容时保留双臂，两臂都空时仍保留原条件一次，嵌套的空 if 也属于控制内容。CLI、Web 和共享过程正文消费相同的原分支身份及条件极性，不在各自输出字符串后再修补括号。

实质内容包括活跃 word 传递、操作、调用、控制转移和诊断。注释与 memory/effect token 是上下文，不单独使分支变为非空，因此显示开关不会改变分支方向；被单臂布局省略的上下文传递仍可在原始 Structured、IR 和来源引用中检查。共享调用按实际选中的替换策略计入内容，展开调用后重新准备计划，过程定义的根节点展开自身而不再次替换为调用。规划拒绝不发布部分布局，原始结构化 AST、高层记录与来源见证均不因显示而改变。

这项空分支显示整理适用于普通分支。失败优先 `if` 的状态传递始终属于原失败体或外层成功续接；开关不会将它重新包装为 `else`。已被 `require` 证书吸收的失败专用传递也不会因开关恢复成另一份失败体。

共享过程记录自 schema version 5 起提供。轻量模型与前端仍接受不含高层投影的旧 version 1、不含 guard 和共享失败证明的旧 version 2、只使用已有空 REVERT guard 的旧 version 3，以及带错误载荷和构造证书的旧 version 4；这些历史产物保留原有结构与证书，高层视图使用同一混合表示选择规则。错误字符串载荷、终结字节证书和构造计划要求至少 version 4，共享过程和调用记录要求 version 5。新增记录采用严格对象字段、字节／字符串边界和独立及合并数量上限，表达式及共享关系按平面引用编码；构造、历史保留和文本展开有资源限制。导出遇到展开上限或取消时报告准确状态，提升中止时保留最后验证的阶段。

这一阶段提供表达式、逻辑活性、跨块复制简化、认证 `require` 与显式失败优先的混合控制表示，以及与格式解码分离的 REVERT 数据与构造证书。被选中 `require` 吸收的失败构造之外，MLOAD、MSTORE、调用和其他 memory 原语均保留；更广的符号内存、字节缓冲区与消费端重建见 [#158](https://github.com/ethever/evm-abstract-lab/issues/158)，其他带数据 REVERT 提升见 [#164](https://github.com/ethever/evm-abstract-lab/issues/164)。

## 阅读转换记录

每份产物都有自己的身份，阶段和节点身份只在相应产物中有意义。源 PC 是字节码位置，不能同时充当分析上下文、复制实例和辅助节点的唯一身份。

转换记录提供以下关系：

| 对象 | 调试时需要查看的关系 |
| --- | --- |
| 原始指令与结果值 | 原始 PC、操作和产生该值的位置 |
| 复制块与复制值 | 原对象、复制实例、引入它的转换 |
| 合成分派控制 | 引入原因和对应原控制流，不伪造原始 PC |
| 改接的边 | 原目标、新目标、参数赋值及所属转换 |
| 简化或移除的对象 | 前后阶段、采用的规则及适用依据 |

用户可以从结果返回原字节码，也可以从原始指令查找所有派生位置。阶段对照展示新增、复制、删除、改接和内容变化；图形布局的折叠或聚合不属于程序语义转换。

结构检查验证身份、定义与使用、边参数及已声明的覆盖关系。它们与针对具体输入的转换前后执行对照共同提供验证证据；检查通过的含义以实际检查项为准。

## 前端工作区

执行分析和反编译共用一个应用入口。反编译工作区拥有独立输入、任务状态、阶段选择与实体选择，不把生成的节点放入 Native 执行状态命名空间。

结构化结果、原字节码、基线 CFG 和选定阶段可以相互定位。前后对照和转换检查器直接消费库生成的来源与变化记录。旧任务的迟到响应不能覆盖新任务；取消请求必须等工作线程清理完毕后才进入终止状态。

结构化代码使用独立的固定状态栏：`N` 表示 New、`C` 表示 Copied、`−` 表示 Removed、`→` 表示 Redirected、`Δ` 表示 Changed；图例和悬浮提示提供完整名称。同一行可以显示多个状态，没有状态时仍保留栏位。代码从统一起点按层级缩进，状态变化不会挤动代码或括号。复制结构化文本保留每层四个空格，不包含状态符号。

例如，要检查代码复制修改了哪里：

1. 打开 `Decompiler`，输入字节码并选择 fork，选中 `Code duplication` 后提交。也可以在执行分析中点击 `Decompile captured source`，带入当前已捕获的代码和 fork。
2. 在 `Transformation history` 选择控制流转换，点击 `Compare transform stages`。`Before stage` 与 `Current stage` 分别指向该转换的输入和输出；`Graphs`、`IR` 与 `Changes` 展示对应差异。
3. 展开 `Copied entities`，分别点击 `Copy original` 和 `Copy descendant`；展开 `Redirected edges` 查看旧目标、新目标与真实边身份。
4. 点击实体的 `Original` 来源，查看原始指令及它的所有派生位置。`Parent occurrences` 和 `Entity descendants` 用于沿转换链前后定位，历史导航保留所选阶段和实体。

选择 `Dispatcher` 时采用同样的检查流程，新增的分派控制出现在转换记录中。两种策略都保留基线；界面中的辅助控制、原指令及复制实例使用各自的身份。

HTTP 入口为 `POST /api/decompile/tasks`，状态和取消分别使用 `GET`／`DELETE /api/decompile/tasks/{id}`，结果使用 `GET /api/decompile/tasks/{id}/result`。请求与结果类型定义在 `evm-abstract-protocol`；任务的 publication 版本与产物内部的 stage 身份分开。

## 实现边界

`evm-bytecode` 提供共享解码、fork 和纯 Word256 求值；`evm-domain` 提供共享数值与符号语义；`evm-resource` 管理工作账本，并复用 `analysis-control` 的取消身份。现有执行分析通过同一份实现继续工作。

`evm-decompile` 负责本地恢复、IR 转换和验证；轻量的 `evm-decompile-model` 保存可传输的 IR、阶段和来源类型。服务端适配请求并使用共享的有界任务调度。前端消费模型和协议，不依赖反编译运行时，也不自行推断转换历史。
