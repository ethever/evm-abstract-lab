# 02：让一份状态代表许多执行

上一课按字节切出了指令和块。这一课先手算两条路径的汇合，再解释分析器用什么值来概括它们。目标是读懂 `{...}`、`⊤`、join，以及“结果保守”具体意味着什么。

本课先用 `--domain constants-only` 手算有限常量集合，再解释默认分析为什么能在“列不完候选值”时继续保留信息。默认 `product` 把常量集合、KnownBits、Interval、Congruence 和 Provenance 放在同一个值中；这些组件的分工与交换机制见[第 12 课](12-product-domains-facts.md)。

本课命令在仓库根目录运行。手算中的无前缀数字是十进制；CLI 用 `0x` 显示十六进制。栈仍按**栈底 → 栈顶**排列。

## 1. 从“可能是 1，也可能是 2”开始

`examples/diamond.hex` 根据 calldata 分支。calldata 是一次调用传给合约的输入字节；`CALLDATALOAD` 从指定偏移读取 32 字节，并解释成一个 256 位数。单字节码分析没有指定这些输入，所以无法选定其中一条分支。

先只看分支结束时的栈：

```text
输入条件非零：PUSH 1 ──→ [1] ─┐
                              ├─→ 汇合 ─→ PUSH 10 ─→ ADD
输入条件为零：PUSH 2 ──→ [2] ─┘
```

执行一次程序，汇合处的值只能是 1 或 2。分析所有允许的输入时，一个槽位需要同时表示两者：

| 步骤 | 栈的摘要 | 含义 |
| --- | --- | --- |
| 汇合前，两条路径分别到达 | `[{1}]` 与 `[{2}]` | 各自只知道一个值 |
| 汇合两条路径 | `[{1,2}]` | 一槽，可能是 1 或 2 |
| 执行 `PUSH 10` | `[{1,2},{10}]` | 两槽，右边的 10 是栈顶 |
| 执行 `ADD` | `[{11,12}]` | 两个输入槽被弹出，压入一个结果槽 |

运行：

```bash
nix run . -- cfg --domain constants-only --file examples/diamond.hex --context-depth 0
```

本课显式使用 `--context-depth 0`，不按跳转历史分组，以便观察同一状态内的值集合汇合。默认值 8 的分组方式留到[第 05 课](05-sensitivity.md)比较。找到 pc=`0x000e` 的汇合状态，当前输出为：

```text
S3 | B3 @ 0x000e | stack height=1 | context=[]
  stack in  [{0x1, 0x2}]
  stack out [{0xb, 0xc}]
```

`0xb` 和 `0xc` 就是十进制 11 和 12。`stack in` 是进入这个块前的栈，`stack out` 是执行整个块后的栈。`S` 与 `B` 的区别留到下一课。

**花括号里的多个数属于同一个槽位。** `[{1,2}]` 的栈高是 1，`[{1},{2}]` 的栈高是 2。

## 2. 抽象值保存的是允许的可能性

一次具体执行的槽位里只有一个数。**抽象值**用一个摘要覆盖多次具体执行中的可能值；指令直接在这些摘要上运算，这就是本实验中的抽象解释。

在 constants-only 对照中，数值有两种形式：非空有限常量集合，以及 `Top`。

允许使用哪些摘要，以及如何比较、汇合和转换这些摘要，共同定义了**抽象域（abstract domain）**。本课使用有限常量集合域解释这些概念。

| 抽象值 | 它覆盖哪些具体值 | 你知道多少 |
| --- | --- | --- |
| `{7}` | 只有 7 | 精确知道这个槽位的数值 |
| `{7,9}` | 7 或 9 | 知道候选值，不能确定选哪个 |
| `⊤`，读作 Top | 任意 256 位值 | 没有进一步的数值限制 |

Top **不是**“没有值”，也不是分析停止。比如未知 calldata word 没有数值限制，后续指令仍然继续分析。

默认组合域需要再区分两件事：**列不出一个完整有限集合**，以及**没有任何数值限制**。前者只是常量集合组件为 Top；其他组件仍可能知道“高 248 位为零”“在 0…255 内”或“最低位为 1”。这些限制共同约束同一个值，数值含义取它们的交集，而不是并集。文本显示 `⊤` 时表示没有数值限制，JSON 仍可能保存 Calldata 等来源标签；来源本身不缩小候选数值。

另一个符号 `⊥` 读作 Bottom，通常表示“没有执行状态”。本实现没有把它做成 `Value`：一个可传播的栈槽位不允许是空集合，私有字段和受控构造函数保证有限集合非空；组合约束可能尚未求解联合存在性，不能把每个组件非空当作整体可达证明；未到达的位置由没有对应状态来表示。

这里有个重要前提：如果分析是 `Incomplete`，没有状态也可能只是尚未展开。必须先检查分析状态与未完成前沿，再讨论不可达，不能把“尚未分析”读成“不会执行”。

## 3. join：把两条路径的信息合在一起

汇合时，一个摘要必须覆盖任一前驱可能带来的值。对有限常量集合，使用集合并集：

```text
{7}   ⊔ {9} = {7,9}
{7,9} ⊔ {9} = {7,9}
{7}   ⊔ ⊤   = ⊤
```

`⊔` 叫 **join（汇合运算）**。它返回当前表示法中覆盖两个输入的最精确摘要。取交集会丢失某条路径；只保留先到达的值也会漏掉后到达的路径。

默认每个集合最多保存 8 个不同常量。超过容量时，常量集合组件升到 Top，而不是删掉部分元素。constants-only 的数值分析只使用这个组件，因此整个数值也变成 Top。用同一个程序缩小容量：

```bash
nix run . -- cfg --domain constants-only --file examples/diamond.hex --context-depth 0 --max-constants 1
```

pc=`0x000e` 现在显示 `stack in [⊤]`、`stack out [⊤]`。容量 1 无法保存 `{1,2}`；Top 虽然允许更多值，却仍包含真实的 1 和 2。若随意删掉 2，才会遗漏真实行为。

用 `a ⊑ b` 表示“b 覆盖 a 的所有可能值”，便得到：

```text
{7} ⊑ {7,9} ⊑ ⊤
         覆盖范围增大 → 信息精度降低
```

这叫**偏序**：不是所有摘要都能比较，例如 `{7}` 与 `{9}` 谁也不包含谁。join 满足交换律、结合律、幂等律，分别保证合并顺序、合并分组和重复输入不会改变结果；[`domain.rs` 的性质测试](../crates/evm-abstract/tests/domain.rs)核对了这些规律。

默认组合域逐组件 join：常量取并集，已知位只保留两条路径共有的固定位，区间取覆盖两者的范围，同余保留共有性质，可能来源取并集。例如容量 1 不能列出 `{1,2}`，但区间组件仍可保存 1…2。join 本身不运行组件间的 facts 交换；这让路径合并与有界精化各自保持清楚的规则，详见[第 12 课的循环与汇合](12-product-domains-facts.md#5-同一值的约束取交不同路径的可能取并)。

## 4. transfer：在摘要上执行指令

**transfer（状态转换）**把输入摘要变成执行指令后的摘要。对有限集合，纯运算尝试每一种输入组合，然后合并结果。例如：

```text
{1,2} + {10,20}
  1+10=11   1+20=21
  2+10=12   2+20=22
结果：{11,12,21,22}
```

枚举所有输入组合叫笛卡尔积。在 constants-only 中，结果超过容量仍升到 Top；输入包含 Top 时，普通算术通常也返回 Top。比较结果本来只可能是 0 或 1，因此容量至少为 2 时，未知比较仍能表示为 `{0,1}`。

按程序顺序串起每条指令的转换，就得到整个基本块的 transfer；下一课的队列以块为单位执行它。

算术必须服从 EVM，而不是主机语言的直觉：

| 规则 | 例子或边界 |
| --- | --- |
| 槽位是 256 位数，`ADD`、`MUL`、`SUB` 按模 2²⁵⁶ 运算 | 最大值加 1 回到 0 |
| `DIV`、`MOD` 的除数为零时，结果为零 | 不产生除零异常 |
| `SHL`、`SHR` 的移位量 ≥256 时，结果为零 | `SAR` 另按符号扩展 |
| 有符号指令按 256 位二进制补码解释 | 最高位为 1 表示负数 |
| 参数顺序是栈顶先弹出 | `SUB(a,b)` 计算 a−b；`SHL(a,b)` 计算 b 左移 a 位 |

非交换运算尤其要手算顺序：

```bash
nix run . -- cfg --domain constants-only --hex 600260030300
```

```text
PUSH 2： [] → [2]
PUSH 3： [2] → [2,3]
SUB：    先弹 3，再弹 2，计算 3−2=1 → [1]
STOP
```

预期 `stack out [{0x1}]`。交换律会让 ADD 的顺序错误不易被发现，SUB 可以直接揭示它。

Osaka 的 `CLZ` 计算 256 位数的前导零数量：最高位为 1 得 0，只有最低位为 1 得 255，全零得 256。未知输入的结果只可能在 0…256，但完整集合需要 257 个常量；CLI 允许的容量是 1…64，所以 constants-only 返回 Top。默认组合域能用区间保留 0…256，并保留结果的高位为零。这是“列不完所有值，仍然知道一些性质”的例子：

```bash
nix run . -- cfg --hex 5f351e00 --domain constants-only
nix run . -- cfg --hex 5f351e00
```

这段代码是 `PUSH0; CALLDATALOAD; CLZ; STOP`。第一条命令的 `stack out` 为 `[⊤]`；第二条没有完整常量集合，但显示的无符号范围为 `u[0x0,0x100]`。是否允许执行 CLZ 由 fork 决定，数值域计算已启用指令的结果。

## 5. 为什么摘要会包含实际不会出现的组合

假设两条具体路径的栈分别是：

```text
路径 A：[1,10]
路径 B：[2,20]
```

逐槽 join 得到 `[{1,2},{10,20}]`。它同时允许以下四种组合：

| 第一个槽 | 第二个槽 | 来源 |
| --- | --- | --- |
| 1 | 10 | 真实路径 A |
| 2 | 20 | 真实路径 B |
| 1 | 20 | 摘要额外允许的组合 |
| 2 | 10 | 摘要额外允许的组合 |

原因是每个槽位单独记录，没有保存“1 与 10 配对，2 与 20 配对”的关系。这是**非关系**表示丢失精度的典型情形。默认组合域增加的是每个值的位、范围等约束，并没有自动恢复任意槽位之间的配对关系。保守分析允许多包含一些行为，但不能漏掉真实行为；因此 CFG 的一条边通常代表可能性，不能单凭它断言存在具体输入能走通整条路径。

默认分析也保留一种范围很小的关系：**基本块内由 DUP 复制出的两个槽位，来自同一次运行时定义**。例如读取一个未知 x 后执行 `DUP1; XOR`，可以使用 `x XOR x = 0`，而不必枚举 x 的数值。两个独立的未知读取即使都有 Calldata 标签，也没有这种相等保证。复制身份在块边界、join 和调用边界失效；它不是跨路径的一般关系求解器，也不能解决未知内存地址是否别名。下一课会观察这种局部关系怎样影响分支，[第 04 课](04-ssa.md)再区分它与 SSA 名字。

[第五课](05-sensitivity.md)会比较保留路径、上下文和数值关系的不同方法。增加集合容量能少丢常量，却不会自动恢复这些配对关系。

## 6. 为什么循环不会要求无限扩大的集合

先看 constants-only 中不断把计数器加 1 的循环。循环入口反复汇合新值时，摘要可能这样增长：

```text
{0} → {0,1} → {0,1,2} → … → {0,…,7} → ⊤
```

一旦变成 Top，再 join 任何值仍是 Top。每个槽位只能严格扩大有限次，这称为**有限高度**。对本课不读写内存/存储、不调用其他账户的例子，固定代码的块数有限，栈高不超过 1024，保留的跳转历史长度也有限；在这些状态键中反复传播，就能达到不再产生新信息的固定点。下一课将实际运行这个过程。

“理论上可以收敛”不保证实际资源够用，工具仍设状态数与执行次数预算，耗尽时报告 `Incomplete`。

默认组合域的区间可能依次扩大为 `[0,0] → [0,1] → [0,2] → …`。虽然 256 位空间本身有限，逐个增加仍可能需要极多轮传播，所以引擎从同一已知状态的第二次严格入口更新起应用区间 **widening（扩大）**：继续向外移动的端点直接扩大到该排序的极值。widening 覆盖已有值和新值，但可能丢失范围精度；它不是普通 join。本实现没有后续通用 narrowing 阶段。

组件间的 facts 交换另有轮数与容量上限。达到这些精度上限时保留已得到的安全摘要；共享工作预算耗尽才会留下未完成前沿。不要把“少做了一轮精化”与“还有程序后继没有展开”混为一谈，具体区别见[第 12 课](12-product-domains-facts.md#6-交换停止与执行未完成是两种边界)。
